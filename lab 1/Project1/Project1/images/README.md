## Контрольные вопросы 

**1. Что такое композиция? Приведите пример.**
Композиция — это отношение, при котором объект-«целое» владеет объектами-«частями». Части не могут существовать отдельно от целого. Если уничтожается целое, уничтожаются и все его части.
*Пример:* Автомобиль и его двигатель. Если автомобиль отправляют на свалку (уничтожают), двигатель как отдельный объект тоже прекращает свое существование (он неотделим от машины в контексте этой системы).

**2. Что такое агрегация? Чем она отличается от композиции?**
Агрегация — это более слабое отношение, при котором объект-«целое» содержит части, но не владеет ими. Части могут существовать независимо от целого. Если целое уничтожается, части продолжают жить.
*Отличие:* При композиции время жизни частей строго привязано к целому (сильная связь), а при агрегации — нет (слабая связь). В C++ композиция обычно реализуется через значения (объекты), а агрегация — через указатели или ссылки.

**3. Как реализовать композицию в C++? Приведите пример кода.**
В C++ композиция реализуется, когда объект-часть является обычным полем (хранится по значению) внутри класса-целого.

```cpp
class Engine {
public:
    Engine() { cout << "Двигатель создан" << endl; }
    ~Engine() { cout << "Двигатель уничтожен" << endl; }
};

class Car {
private:
    Engine engine; // Композиция: двигатель является частью машины
public:
    Car() { cout << "Машина создана" << endl; }
    ~Car() { cout << "Машина уничтожена" << endl; }
};
// При удалении объекта Car, автоматически вызовется деструктор Engine.
4. Как реализовать агрегацию в C++? Приведите пример кода.
В C++ агрегация реализуется через указатели или ссылки. Класс-целое не управляет временем жизни частей.

cpp
class Student {
public:
    string name;
    Student(string n) : name(n) {}
};

class University {
private:
    vector<Student*> students; // Агрегация: храним указатели
public:
    void addStudent(Student* s) {
        students.push_back(s);
    }
    // При уничтожении University деструктор Student НЕ вызывается.
};
5. В чём разница между временем жизни частей при композиции и агрегации?

Композиция: Время жизни части полностью контролируется целым. Часть создается вместе с целым и уничтожается вместе с ним.

Агрегация: Время жизни частей не зависит от целого. Части могут быть созданы до целого и продолжать существовать после его уничтожения.

6. Что такое статическое поле класса? Чем оно отличается от обычного поля?
Статическое поле — это переменная, которая принадлежит всему классу, а не конкретному объекту.
Отличие: У обычного поля у каждого объекта своя копия. Статическое поле существует в единственном экземпляре для всех объектов класса. Если один объект изменит статическое поле, это увидят все остальные объекты.

7. Как объявить и определить статическое поле? Где оно хранится?

Объявление происходит внутри класса с ключевым словом static: static int count;

Определение (выделение памяти) происходит вне класса (обычно в .cpp файле): int MyClass::count = 0;

Где хранится: Оно хранится не в памяти объектов, а в статической области памяти (сегменте данных) программы.

8. Что такое статический метод? Можно ли из него обратиться к нестатическим полям?
Статический метод — это метод, который привязан к классу, а не к объекту. Его можно вызывать без создания объекта (ClassName::Method()).
Нет, нельзя. Статический метод не имеет доступа к нестатическим (обычным) полям и методам, так как он не привязан к конкретному экземпляру (у него нет указателя this).

9. Для чего используются статические счётчики объектов?
Они используются для подсчета количества созданных на данный момент объектов класса (как в вашей лабораторной). В конструкторе счетчик увеличивается, а в деструкторе — уменьшается. Это позволяет отслеживать утечки памяти или просто вести статистику.

10. Что такое паттерн «Одиночка» (Singleton)? Для чего он нужен?
Это порождающий паттерн проектирования, который гарантирует, что у класса есть только один экземпляр, и предоставляет глобальную точку доступа к нему.
Нужен для: управления подключением к базе данных, настройками конфигурации, логгерами и т.д., когда создание нескольких объектов может привести к конфликтам или избыточному расходу ресурсов.

11. Как запретить создание копий объекта (конструктор копирования)?
Нужно объявить конструктор копирования и оператор присваивания как delete (в современном C++) или сделать их приватными (в старом C++).

cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete; // Запрет копирования
    NonCopyable& operator=(const NonCopyable&) = delete; // Запрет присваивания
};
12. В каком порядке вызываются конструкторы и деструкторы при композиции?

Конструкторы: Сначала вызываются конструкторы для полей (частей) в том порядке, в котором они объявлены в классе, а затем — конструктор самого класса-целого.

Деструкторы: В строго обратном порядке. Сначала вызывается деструктор класса-целого, а затем деструкторы его полей (в обратном порядке их объявления).

13. Можно ли изменить статическое поле из обычного метода?
Да, можно. Обычный метод имеет доступ к статическим полям класса. (А вот статический метод к обычным полям доступа не имеет).

14. Почему статические поля нужно определять вне класса?
Потому что объявление внутри класса (например, static int count;) — это только декларация (сообщение компилятору о том, что такое поле существует). Компилятору нужно знать, что переменная существует, но память под нее не выделяется. Выделение памяти (определение) должно происходить один раз в программе, поэтому это делается вне класса (чаще всего в .cpp файле).

15. В каких случаях стоит использовать композицию, а в каких - агрегацию?

Композиция используется, когда объекты образуют единое целое, и один объект не имеет смысла без другого (например, "Заказ" и "Строка заказа"). Части являются неотъемлемой частью целого.

Агрегация используется, когда объекты связаны, но могут существовать друг без друга (например, "Университет" и "Студент", "Автопарк" и "Машина", как в вашей лабораторной). Это отношение "имеет" (has-a), но без жесткого владения.
